# AGENTS.md

## 1. What this is

A static, offline teaching app for Khan Academy Trigonometry Unit 4. One page, three interactive studios: inverse functions with restricted domains, a Pythagorean-identity simplification lab, and an equation/identity practice sandbox. It produces no build output and talks to no server; it is not a Khan Academy clone, a course platform, or a graded assessment tool.

Current release: **v1.0.0** (2026-11-03).

Live copy: <https://somphol.github.io/khan-trig-unit4-equations-identities-studio/>
Local master: `~/Projects/khan-trig-unit4-equations-identities-studio`

## 2. Commands

```bash
# run (no install, no build)
python3 -m http.server 8080
# then open http://localhost:8080

# syntax gate
node --check script.js

# deploy = push to main; GitHub Pages serves the repo root
git push origin main
```

Opening `index.html` via `file://` also works. There is no test runner in the repo; verification for 1.0.0 used headless Chrome over the DevTools protocol (inverse branches, identity steps, equation answers, language switch, reload, export, mobile) and produced zero console errors.

## 3. Architecture

Load order is `index.html` → `style.css` → `script.js`. `script.js` is one IIFE:

1. `I18N` dictionaries (`en`, `th`), `t()` and `L(en, th)`.
2. `DEFAULT_STATE`, `loadState`/`saveState` (localStorage key `khanTrigUnit4.v1`).
3. Angle helpers: `piFrac`, `radToPi`, `fmt`.
4. Inverse engine: `FUNCS`, `inverseState`, `drawInverse`, `renderInverse`.
5. Identity engine: `EXPRESSIONS`, `renderIdentity`, `chooseIdentity`, `drawAreaModel`.
6. Practice engine: template data, generators, parser, `renderPracticeCanvas`, `revealSteps`.
7. Tabs (`showModule`), i18n (`applyI18n`), export, boot.

`style.css` follows the semantic palette (`--sin`, `--cos`, `--tan`, `--one`, `--theta`) and then HUD → tabs → cards → canvas → controls → module-specific → responsive. `state.json` is a historical build record, **not** runtime state.

## 4. Decisions and constraints

- **Keep the five colours semantic.** Coral is sine, cyan is cosine, violet is tangent, emerald is the value 1 / the inverse, yellow is angles. The area model and inverse curve depend on this.
- **Principal domains live in `FUNCS`.** sin `[−π/2, π/2]`, cos `[0, π]`, tan `(−π/2, π/2)`, with ranges `[−1, 1]`, `[−1, 1]`, `ℝ`. A domain is valid only when it is contained in the principal branch; an input is valid only when it is in the original function's range.
- **Domain sliders store multiples of π/12** (`minK`, `maxK`). Never store pixels or decimals for the branch endpoints; exact display comes from `piFrac`.
- **The inverse curve is generated by sampling `x = f(t)` over the chosen domain**, not by swapping stored points. Keep the sampling and the drawing in sync.
- **Identity steps are data.** Each `EXPRESSIONS` entry lists prompts, bilingual explanations, exactly one correct choice per step, and the resulting expression. Adding a step means adding data, not branching UI code.
- **The area model is a square construction.** Squares are built on the triangle's three sides and labelled with squared lengths; only square captions are drawn to avoid label collisions inside small triangles.
- **Equation answers are sets.** The parser accepts `π/6`, `5π/6`, `0.5236` and degrees; comparison normalises modulo 2π and ignores order. Do not switch to string equality.
- **Step reveal uses timers.** `resetStepAnimation()` must clear every timeout and hide revealed solutions before a new problem.
- **Canvas scaling:** every canvas uses a `ResizeObserver` and a DPR clamp of 2. Hidden panels resize when shown.
- **i18n must stay symmetric:** every key exists in both `en` and `th`; static text uses `data-i18n*`, dynamic text uses `t()`/`L()`/bilingual data.
- **Persistence is best-effort:** storage failures are swallowed so private mode still works in memory. The export filename is fixed at `khan_trig_unit4_progress.json`.
- **No dependencies and no network calls.** Do not add a framework, CDN, web font, analytics or remote image. The app must work from `file://`.
- **`state.json` is a snapshot.** It records the build session and is not written by the app.

## 5. Known issues

- The inverse canvas is information-dense; at very narrow widths the axis labels and the drag hint sit close together.
- The area model is qualitative, not to scale for every expression; square captions carry the exact meaning.
- Identity practice uses the same seven expressions as the lab; it is a recognition check, not a free-form proof editor.
- Basic/quadratic answer lists accept radians or degrees, but mixed formats in one submission are not supported.
- Thai copy is longer than English; very narrow screens wrap rather than truncate.
- `localStorage` on `file://` is per-browser-profile and can behave differently from an HTTP origin.
- Safari and Firefox are expected to work but were not formally verified for 1.0.0.
